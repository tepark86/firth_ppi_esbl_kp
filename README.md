# Firth penalized logistic regression for the PPI / ESBL *K. pneumoniae* bacteremia study

Analysis code accompanying:

> Lee YB, Lee J, Choi H, Park TE, Lee CS. Outpatient proton pump inhibitor use and clinical
> outcomes in community-onset extended-spectrum beta-lactamase-producing *Klebsiella
> pneumoniae* bacteremia: a retrospective cohort study.

Every adjusted odds ratio reported in that paper was produced by the Firth penalized
logistic regression in [`firth.py`](firth.py), which was written for this study rather
than taken from an existing package. This repository exists so that the implementation,
and the two checks used to verify it, can be inspected and re-run independently.

## Why a custom implementation

The cohort has 62 patients and 11 deaths. With sparse strata and at least one covariate
that is perfectly predictive, ordinary maximum likelihood either diverges or returns
Wald intervals that are not trustworthy. Firth's penalized likelihood, `L*(b) = L(b) +
0.5*log|I(b)|`, gives finite estimates under separation, and profile penalized-likelihood
intervals are preferred to Wald intervals in that setting (Heinze and Schemper 2002).

## Contents

| File | Purpose |
| --- | --- |
| `firth.py` | The implementation: modified-score IRLS fit, profile penalized-likelihood confidence intervals, penalized likelihood ratio test |
| `validate_firth.py` | The two verification checks reported in the paper |
| `make_example_data.py` | Generates the synthetic cohort below from a fixed seed |
| `example_data.csv` | Synthetic 62-patient cohort, so the validation runs without the real data |

## Running it

```bash
pip install -r requirements.txt
python validate_firth.py
```

Expected result: both checks PASS.

**Check 1, closed-form equivalence.** For a saturated model with a single binary
covariate, Firth penalization is exactly equivalent to adding one half to each cell of
the 2 x 2 table. This check runs on the published 2 x 2 table of outpatient PPI use
against in-hospital mortality, `[[4, 13], [7, 38]]`, an aggregate reported in Table 1 of
the paper. It therefore reproduces the exact figures quoted in the manuscript, 1.7111120
against a theoretical 1.7111111, with no patient-level data.

**Check 2, independent optimizer.** The same penalized log-likelihood is maximized with a
general-purpose derivative-free optimizer (Nelder-Mead refined by Powell) instead of the
modified-score IRLS, and every coefficient must agree. This check needs patient-level
covariates, so on a fresh clone it runs against `example_data.csv` and demonstrates
agreement to better than 1 part in 10^4. It does **not** reproduce the exact relative
difference quoted in the paper, which was computed on the real cohort. With access to the
real file, run `python validate_firth.py --data <file>` to reproduce that figure.

## Data availability

The patient-level data cannot be released. They are identifiable clinical records from a
single center, held under institutional restrictions and covered by the IRB approval for
this study; they may be requested from the corresponding author subject to institutional
approval. `example_data.csv` is synthetic, generated by `make_example_data.py` from a
fixed seed, and corresponds to no real patient. It shares the column names, coding, and
approximate marginal frequencies of the real cohort, and reproduces the empty urinary
source stratum, so that the separation behaviour Firth penalization was chosen for is
exercised. Its joint structure is otherwise random, and no estimate computed from it
should be read as a study result.

## Using `firth.py` on your own data

```python
import numpy as np
from firth import firth_logit, firth_profile_ci, firth_lrt_pvalue

X = np.column_stack([exposure, covariate])   # no intercept column, one is prepended
res, loglik = firth_logit(X, y, var_names=['exposure', 'covariate'], ci='profile')
for r in res:
    print(r['var'], r['OR'], r['lo'], r['hi'])

lo, hi = firth_profile_ci(X, y, idx=0)       # profile CI for the first column
p, stat = firth_lrt_pvalue(X, y, drop_idx=0) # penalized likelihood ratio test
```

`firth_profile_ci` returns `inf` on a side where the interval is unbounded, which happens
under complete separation and is the correct answer rather than an error.

`firth_lrt_pvalue` fits the restricted model by maximizing the penalized log-likelihood
subject to the tested coefficient being zero, with the Jeffreys penalty still evaluated on
the full design matrix, as `logistf` does. Refitting the reduced model on a smaller design
matrix would change the penalty term, so the two penalized log-likelihoods would sit on
different scales and their difference would not be a chi-square statistic; that variant
returns p-values that are systematically too small. Keeping the full-model penalty also
makes the test agree with `firth_profile_ci`, so a 95% profile interval excludes 1 exactly
when the reported p is below 0.05.
